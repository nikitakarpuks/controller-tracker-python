## Live-condition spec (current tree)
- Start state = filter's last committed pose self.R,self.p at last_update_ts_ns (pose_fusion_heuristic.py:705-757 predict()); a blend, can be a weak accept (walk_medium right 333 had inlier_count 2).
- Velocity self.v = plain 2-point finite difference (p_new-p_prev_state)/dt_s between last two committed states (lines 1801-1809); velocity_established set True there; False on bootstrap/cold-reacquire/_rot_seed_untrustworthy (194,1254,2567,2619). No smoothing.
- Headset ego-motion: predict() uses _predict_with_headset_correction whenever self._headset_mocap is not None (730-745, 759-780). main.py:240-275 loads headset mocap when mocap.enabled (config.yml:915 = true) => CURRENT TREE USES MOCAP HEADSET pose/ang-vel/lin-vel (dev-only). Without it predict() falls back to predict_world_pose in the rig frame ignoring headset motion completely (746-757). There is NO headset-IMU ego-motion in the code.
- Gravity: with mocap constant MOCAP_ROOM_G_WORLD=[0,-9.81,0] (imu_data.py:903); the live g_world_estimator_abs is commented out. Fallback: LiveGravityEstimator in rig frame (imu_data.py:853-886), needs 20 quiet samples |gyro|<=0.5 rad/s.
- Lever arm accel_lever_arm_body (body frame), lag = -mocap_vision_offset_ns, loader factory-corrected + accel scale 0.980665.

## Limitations
- Headset ego-motion is mocap (dev-only); no headset-IMU substitute tested. Anchors = strong accepts (>=7 inliers) with velocity gap <=0.1 s, biased to calm/tracked moments, not coast-onset representative. Peak gyro/accel measured over the same window as the error (higher-dt rows in a bin more violent). 09-22 accepts come from an older tracker (only vision pose reused).
